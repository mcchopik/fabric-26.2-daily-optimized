# Аудит GitHub mcchopik

Дата: 2026-11-04

Проверены 10 доступных репозиториев аккаунта. Изменений в них во время аудита
не выполнялось.

## Сильные стороны

- У `noverplay-26.2` есть MIT-лицензия, CI, wrapper validation и релиз.
- `Sborka` хорошо документирует установку, происхождение модов и ограничения.
- `moduhub-modules` сверяет размеры и SHA-256 опубликованных модулей.
- В публичных репозиториях включены secret scanning и push protection.
- Workflow `female-gender-26-2` использует точные SHA GitHub Actions.

## Главные риски

1. В `ytmusic/src/main/java/dev/mcchopik/ytmusic/auth/DeviceAuthService.java`
   OAuth-параметры встроены в код и попадут в каждый JAR. Если secret считается
   закрытым, его нужно отозвать и перейти на OAuth public-client flow.
2. `Site` и `Lorcopika` не имеют лицензий и почти не описаны на главных страницах.
3. В Gradle используются вручную закреплённые зависимости и mutable SNAPSHOT;
   Dependabot и проверочные суммы Gradle distribution не настроены.
4. Автотестов нет; CI в основном подтверждает только успешную компиляцию.
5. В `Lorcopika` продукты разделены по веткам, общий код дублируется, PR-проверки,
   защищённые ветки и постоянные релизы отсутствуют.
6. `Sborka` и `wildfire_gender_decompiled` хранят много сторонних бинарников,
   что усложняет проверку происхождения и лицензий.

## Рекомендуемый порядок действий

1. Проверить и при необходимости отозвать OAuth secret в `ytmusic`.
2. Оформить профиль: имя, bio, profile README, закреплённые проекты и topics.
3. Добавить лицензии и нормальные README в `Site` и `Lorcopika`.
4. Подключить Dependabot/Renovate, убрать mutable SNAPSHOT и добавить тесты.
5. Публиковать бинарники через Releases с checksum и перечнем исходников.

Секретные значения в этот отчёт не переносились.
